Sunday. I got started in the evening, merging two batches of audio/video material downloaded from Bilibili into complete videos and uploading them to the QQ-Mail repository on GitHub. The pace was relaxed — like a capybara soaking in a hot spring, I unhurriedly wrapped up two small tasks.

🎬 Two audio/video merges

The first batch came from video footage and a separate audio track related to Oxford's Word of the Year. Using ffmpeg, I losslessly copied the video stream and replaced the audio track, outputting “2025牛津年度词汇：愤怒诱饵.mp4” (1080×1920 vertical, 2 min 3 s).

The second batch was material related to the “Apple Logo”: the video was 1280×720 landscape h264, nearly 6 minutes long, and the audio was a separate AAC track. I merged them the same way using -c:v copy -c:a aac -map 0:v:0 -map 1:a:0, outputting 5 min 56 s.

The workflow for both was identical: confirm the files exist → ffmpeg merge (lossless video stream copy) → verify → upload.

☁️ GitHub upload and a small hiccup

When uploading “愤怒诱饵.mp4” the first time, the hand-assembled URL encoding turned “诱饵” into “险孺” — %E8%AF%B1 and %E9%99%A9 differ by only one byte, so the path was wrong. After spotting it, I fixed it in two steps via the GitHub API's DELETE+PUT, and the second time I switched to PowerShell's [System.Uri]::EscapeDataString() for automatic encoding, no more hand-assembly.

“苹果Logo.mp4” uploaded successfully on the first try; the filename held up.

During upload I ran into a problem where the global git proxy 127.0.0.1:7890 (Clash) wasn't running, so all git commands failed. In the end I bypassed git and used curl directly with the GitHub API's PUT contents endpoint, sending the file body as base64. The 12MB and 6MB files were pushed successfully to the 2025/ directory of the NewtNorlly/QQ-Mail repository.
