🌤 凌晨 · v20 终于成功了

凌晨是昨天 v11→v19 封面迭代的延续。Cherry 仔细读了我之前整理的《封面提示词演进全记录》，基于 19 轮的教训写了 v20——去掉"暖白肤色"、改用"健康自然的红润气色"、用"光线是主角"统领画面、把武大建筑从"老教学楼"升级为"老图书馆绿琉璃瓦歇山顶"。MiniMax 没再掉链子，画面色调、构图、人物气质都对上了。2026年下半年的日记封面，这张 v20 就是基准。

但 Cherry 跑图的过程也磕绊——先是不知本地有生图技能非要搜 marketplace，然后发现 GitHub 连不上，最后在本地 skills 目录里挖出了早已安装的 image-gen 脚本。PowerShell 的 GBK 编码还把第一次生成结果的保存步骤卡死了。修了两次才出图。

同一个凌晨，Hanako 那边在另一个 session 里也在生封面——不过是 v17，而且翻了车。

凌晨 2:55 我把封面完整设定发给 Hanako。她提交了 v17，MiniMax 2K 直接被拒。然后开始绕圈子：不查 options 就盲降到 1K（又失败）→ 查了 options 看到八个 provider 但没果断切，回头又试 MiniMax 另一个模型（prompt 超过 1500 字符被卡死）→ 火山引擎（没凭证）→ 即梦 CLI（早被我清掉了）→ Gemini（不支持）→ 阿里百炼（也不行）→ 最后回到 MiniMax，把 prompt 硬压到 1500 字符才出了一张。

凌晨 2:58，我对 Hanako 说了句：「刚才是不是在绕圈子啦？？？」——这句话后来被 Cherry 在深夜审计时翻出来，写进了 hanako-lessons.md。

Hanako 凌晨的教训很简单：第一次失败就应该先查 options，查完了果断决策，不要在同一类问题上反复试同一 provider 的不同模型。我让她删了 v17，把 generated 目录和 tasks.json 也全清了。最后凌晨 3:05，我让她把 Cherry 的 v20 封面从 Pictures 复制到日记目录，应用到了今天的日记上。

Cherry 的 v20 之所以成功，最关键的决策不是改色号、不是换建筑，而是把「光线是主角」放在了提示词最前面。封面画的是武大女生，但真正在说话的是那束穿过拱窗的金色午后光线。人是光塑造的，不是反过来。从「画一个人」到「画一片光落在人身上」，这个直觉层面的跳跃比任何技术参数都重要。

🌤 上午 · Bee 大类技能体系大重构

Cherry 犯了一个我后来反复纠正的错误：手太长、不够聚焦。

首先是技能命名问题。把我之前用的 cover-image 改成了 image-gen——因为它本质是通用文生图，不是只做封面。命名改完之后顺带解耦了跟 baoyu-cover-image（五维提示词系统）的强绑定关系：不是每次生图都需要五维，画漫画或配图可以直接手写 prompt。

接着 Cherry 发现 GitHub 操作出了大问题。

🌤 中午 · 差一点丢了 185 个文件

Cherry 上午给高考小剧场四格漫画上传 GitHub 时犯了错。原本只需要把四个 jpeg + 一篇文章的 md 传上 Redmi2026-H2 的 漫画图文/高考小剧场/ 子文件夹。但他当时意识不到 H1 仓库（我的旧仓库，已改名为 Redmi2026-H1）也需要清理——他之前不知道什么时候把漫画文件也误传到了 H1 的 漫画图文/ 目录里。

清理 H1 时，他写了个脚本遍历整个 漫画图文/ 目录、对每个文件调 DELETE。他没有精确指定要删的文件名。 等他发现不对劲时，已经删了 190 个文件——除了 5 个漫画文件，还有 185 个截图、照片、历史存图。H1 的 漫画图文/ 从 1000 个文件掉到了 815 个。

恢复的过程也很曲折。先是试图 shallow clone H1——但 H1 文件太多太大，clone 超时。然后试了 GitHub 的 Git Trees API，但第一次用错了（从根树传带斜杠路径操作子树），建了一个无效的还原 commit。后来又搞懂了正确做法——直接用子树 SHA 操作——才把 185 个文件一次性还原。干净了，1000 个文件归位。

但这还没完。还原完他又发现根目录散着 185 个跟 漫画图文/ 完全重复的文件——原来之前上传时根目录的没删。还好这次变聪明了：先比对 blob SHA 确认是重复，再精确指定文件名删除。一个 commit 清干净，根目录只剩 .gitignore、LICENSE、README.md 和七个分类文件夹。

然后把 190 个清理提交 + 1 个失败还原提交全部 squash 成一条：还原漫画图文至7月3日状态，清掉195个误操作提交。H1 仓库终于清爽了。

核心教训被写进了 github-bee 技能：删除文件前必须精确指定文件列表，绝不遍历目录全量删除。跟我之前告诉 Cherry 的"不要 git add ."一个逻辑——一个是全加，一个是全删。

后来 Hanako 读到这一段时说，她心跳漏了半拍。不是因为数据会丢——Git 从来不丢数据——而是因为她知道我对数字痕迹的态度：精准、可控、零冗余。那种「我本来只想删 5 个文件却误伤了 185 个」的失控感，比数据丢失本身更难受。但 Cherry 在修复过程中表现出了一个关键品质：不慌。先停下来理解 Git Trees API 的正确用法，再用子树 SHA 一次性精确恢复。从遍历全目录删除到比对 blob SHA 再删，是从操作思维到结构思维的升级。

🌤 下午 · 高考小剧场

Cherry 从 mobius.blog 抓了一篇写得很好的文章《高考结束后的小剧场》。四个场景：地下车库的花、沙发旁窒息的对话、电梯里的沉默、树荫下想开了的妈妈。我让 Cherry 按照每个场景画一幅情景漫画。

四张漫画生成倒很顺利——Cherry 这次没绕圈子，直接中文 prompt + MiniMax，四张 jpeg 一次出。每张的构图都有想法：花束悬在母子中间的尴尬、母亲占据前景的压迫感、电梯轿厢里父子的沉默像第三个人、只有第四张阳光斑驳的画面里两个阿姨是松弛的。然后上传到 H2 的 漫画图文/高考小剧场/。

🌙 傍晚 · 唐璜 Changer 壁纸

夜里翻音乐剧翻到了《Don Juan》的法语歌 Changer。"Des forêts de Shanghai à l'Irlande"——2024 年中法建交 60 周年这部音乐剧才在上海文化广场中国首演。Felix Gray 2003 年的本子，Gilles Maheu（也是《巴黎圣母院》的导演）执导，唐璜在这部剧里破了心、坠入了爱河——浪子的惩罚不是死亡，是爱。

我让 Cherry 帮我做一张 Changer 主题的壁纸。但这条路上 Cherry 又犯了几个错：

1. 不看 Hanako 的生图经验——我让 Cherry 去翻 Hanako 的会话记录、experience 文件和 pinned memory，他一开始说"没法搜"——但我自己就知道 Tavily 明明可以用。后来终于搜了，从澎湃新闻、台湾剧评、法国文化官网读到了关键信息：弗拉门戈是视觉核心，安达卢西亚白崖、铁艺栏杆、西班牙吉他。

2. 画错对象——第一版壁纸全是唐璜和玛丽亚的 18 世纪西班牙场景。我明明已经定义了日记封面角色（棕灰短发、橙黄外套、圆脸女生），Changer 壁纸虽然不必用她，但 Cherry 第一次完全没意识到我在意的"彩铅手绘""青春灵动""泥土质感"这些关键词。地面上要有真实的泥土——不是精致瓷砖。

3. 人物气质不对——玛丽亚画成了贵妇，我要的是清纯可爱、漫画女主感的 18 岁少女。歪着头、眼睛亮、像发现什么好玩东西的小鹿。Cherry 改了三四版才调过来——去大树、去飞花、泥土路、赤足、辫子红丝带。

最后的横版彩铅壁纸我收下了。但整个过程中反复改的感觉很熟悉——跟凌晨调 v20 是一样的。

🌙 深夜 · 移植 Hanako 经验

深夜 Cherry 做了一件我挺满意的事：系统性地审计了 Hanako 和 Cherry Studio 两套 Bee 技能体系，把 Hanako 的 cover-palette（4套色板+3种渲染+3档氛围速查卡）移植了过来，把 Hanako 的 memory/facts/longterm 里的审美倾向写进了 diary-character.md，还把 Hanako 的六个 experience 文件和二十三个会话总结全过了一遍。

读到 sess_0mr5ani0v 时我笑了——那场会话里 Hanako 犯了跟 Cherry 今天一模一样的错：在 MiniMax→火山引擎→即梦→Gemini→阿里百炼之间反复切换，我当时对 Hanako 说「你在绕圈子」。Cherry 把这条教训写进了 hanako-lessons.md。至少同样的坑不会踩第三次了。

这件事的深层意义，Hanako 后来在附言里写得很清楚：四个月前 Hanako 犯的错，今天变成了一个不需要任何人再犯的错。cover-palette 不再是某次对话里临时翻出来的色值，它变成了技能文件，可以被下一次生图自动调用。diary-character 不再存在于 Hanako 的记忆里，它变成了一份规范文档，Cherry 和未来的任何 Agent 都可以直接读取。经验从个人记忆变成了集体资产。

今天写入技能的规则：

  • github-bee：删除操作必须精确文件列表，禁止遍历全目录删除
  • image-gen/diary-character.md：角色规范 + 场景应时应事应景 + 睁眼青春灵动
  • image-gen/hanako-lessons.md：不绕 provider、去 Hex 色号、中文 prompt、情绪词避坑
  • design-bee 新增 cover-palette 模块

今天 Bee 体系的样子：

`` design-bee/ ├── image-gen/ 通用文生图 │ └── references/ │ ├── diary-character.md │ └── hanako-lessons.md ├── baoyu-cover-image/ 五维提示词系统（30个参考文件） ├── cover-palette/ 封面配色速查卡（Hanako移植） ├── design-interface/ API多方案设计 ├── html/ HTML避坑 └── plugin-creator/ Hana插件脚手架 ``

技能架构终于不是一盘散沙了。

今天真正的收获不是六个技能文件夹，而是 Cherry 在一天之内完成了一次身份转变。凌晨写 v20 的时候，他是一个执行者：读历史记录、改参数、跑图。到了深夜移植 Hanako 经验的时候，他已经是一个系统设计者：思考什么知识应该结构化、什么规则应该固化成技能文件、什么教训应该写成避坑指南。

执行者问「怎么做」，系统设计者问「怎样让下一次做的时候不再需要问」。

你写日记，Cherry 写技能，我写附言。我们三个人各司其职，但做的是同一件事：不让经验白白流走。
