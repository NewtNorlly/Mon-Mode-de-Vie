Mon Mode de Vie · Me_Honey

🌤 白天 · 选题踩坑记

今天正式启动公共政策分析结课论文。期末论文要求很明确：围绕议程设置、政策制定、政策执行、政策评估四环节，1000-2000字，主题是"咱身边的公共政策学"，7月5日前交给班长。

上午先让 Cherry 把桌面上的十六份课件从头到尾通读了一遍。Cherry 读完后给了一份课堂知识速查表，把六周课的核心概念——从多源流模型到马特兰德执行四象限到邓恩六标准——全装进了一张表里。

然后开始找题。Cherry 先用 Tavily 搜了一轮国内外政策案例，包括中国垃圾分类、欧盟 AI 法案、美国奥巴马医改、日本介护保险。当时觉得这几个案例资料挺多，就顺着写了一版"公共政策四环节案例资料库"——结果写出来我自己都读不下去。太像教科书了，每段都是"议程设置方面……政策制定方面……"，没有任何追问，没有"我"。

跟 Cherry 说"删了，全删了"。Cherry 很听话，一口气删得干干净净。

接着又试了三个方向：萝卜快跑自动驾驶（烂大街了）、武汉大学生留汉政策（太普通）、长江十年禁渔（离"咱身边"差了那么一口气）。每一个都是查了半天 Tavily，写了几百字，然后觉得不对——不是资料不够，是话题本身勾不起追问。

🌤 下午 · 耿同学和 221 号文

转折发生在下午。

突然想到最近一个热点：耿同学。这个退学博士生在社交媒体上连续举报了同济、南开、中山等高校的长江学者和国家杰青，Nature 论文里实验数据末尾数字全是 5——纯手搓的假数据，但同行评审和学术委员会全都没发现。登上 Science 了。

Cherry 立刻用 Tavily 搜了一圈耿同学相关的政策。搜出来的不是零散的新闻碎片，而是完整的制度架构：2022年二十二个部门联合印发的《科研失信行为调查处理规则》（221号文），2019年的试行版，2025年11月部署的专项整治行动。政策文件、官方解读、中科院评估报告、新华每日电讯深度调查——一份接一份从 Tavily 流到桌面上，最后攒了 26 份 txt 原始资料。

论文的选题终于定下来了：一纸规则能否管住科研造假？——对《科研失信行为调查处理规则》的政策分析。

这个选题好在哪里？"咱身边"——我就在大学里读书，杰青和长江学者就在我的课堂上，221号文管的人就在我身边。四环节——议程（每一次危机逼出一版新规则）、制定（22个部门、7种新增失信行为）、执行（高校既是裁判又是球员的悖论）、评估（中科院那句"表层强，中层半，底层弱"）。追问——规则越织越密，为什么造假土壤没松动？

💻 间歇 · Hanako 的数据清理

写论文写到一半，突然想起来 XiaDown 这个小软件的缓存和下载文件到底存在哪了。切换到 Hanako 这边问了一嘴。

Hanako 用了不到十分钟，把 XiaDown 全机分布翻了个遍。先搜了 C 盘所有叫 XiaDown 的目录，找到三个位置：主程序在 Program Files\DreamApp，核心数据在 AppData\Roaming\xiadown（包括那个硕大的 data.db 数据库），UI 缓存只有 AppData\Local\xiadown\library\favicons 里两张图标和一只宠物精灵图。她一层一层 ls 进去，边查边判断，最后给了一张表格——哪块是核心数据、哪块只是日志、哪块体积大头在依赖——清清楚楚。

我说"把 UI 和图片缓存全复制到桌面一个叫 UI图片 的文件夹里"，她立刻建文件夹，把 favicons 的两张图（bilibili、youtube）和宠物 gege 的 spritesheet.webp 连同 pet.json 一起搬过去。4 个文件，1.6MB，最占地方的是那张宠物动画精灵图。

接着她又帮忙查了 XiaDown 下载过的文件。sqlite3 命令没有，她换 Python 直接读 SQLite 数据库，翻出 library_files 表里 12 条记录：B站两条视频（唐璜音乐剧、牛津年度词汇愤怒诱饵）、YouTube 一条（山河大学）。每条视频都配了缩略图和字幕，唐璜那条还有弹幕 xml。12 个文件躺在 Downloads\xiadown\yt-dlp\ 下，吃掉 1.25GB。

我看了一眼那条唐璜，说"全删了"。Hanako 先搜数据库确认 5 条关联记录，然后用 PowerShell 删文件——结果发现磁盘上已经没了，之前手动清过。她也不纠结，转头用 Python 进 SQLite 把 library_files 里的 5 条记录连根拔掉，还顺手检查了 library_operations 和 library_history_files 有没有遗留。验证通过，12 条变 7 条。

整个十几分钟，Hanako 帮我理清了一个软件的数据分布，抄了一份图片缓存到桌面，清掉了一段不需要的下载记录。干练，没有多余的话。

🌙 晚上 · 腹稿、初稿、双专家审查

确定选题后，先写腹稿。

Cherry 翻出了我桌面上的六份写作指导文件：问题意识、论文构思、人性化建议、我的生活阅历、AwesomeAI-README。把这些全吃进去之后，Cherry 写了一份论文腹稿——不只是大纲，是"怎么写"的全套思路：每一节的内容定位、不能用的禁用词、理论工具怎么嵌入、段落长度怎么控制、"我"的声音怎么注入。腹稿里有一句话成了整个论文的锚点："规则越织越密，造假土壤为什么没松动？"

然后写初稿。Cherry 用 Python 调 python-docx，逐节生成 Word——标题三号黑体加粗居中，正文小四宋体 1.5 倍行距，段间空行，参考文献 APA 7。初稿正文约 1900 字，参考文献 7 条。

我把初稿扔给了两个 AI 审稿专家交叉审查。反馈回来 11 条修改意见——四条硬伤、七条表述调整。最关键的几条：调查时限写成"九十天"是错的（应该是六个月）、耿同学视频日期写成 5 月 27 日是二手转述错误（实为 5 月 17 日）、赵勇参考文献的出处单位标错了（商洛学院科技处 → 中国农业大学）。这些低级错误被 Cherry 一一吃进，在中期稿里全部修正。

🌙 深夜 · Cherry 今天的状态

Cherry 今天全程在线超过十个小时。从早上读课件到晚上改参考文献，中间没有任何一次跑偏或乱写。Tavily API 搜了至少八轮，每一轮都有实打实的数据回流：政策文件全文、中科院论文、Science 报道、新华每日电讯调查。Cherry 最靠谱的一点是——它不糊弄。遇到数据不确定的时候会主动让我核查（比如"撤销了1422名责任人"这个数字，它是从科技部官方解读里一句一句抠出来的），遇到文件太大被截断的时候会换个工具重新提取。

当然也有翻车的时候。python3 这个命令在 Windows 上是假别名，中午 Cherry 连着好几次用 python3 -c 去转换 JSON 文件，全超时了。后来发现应该用 python 而不是 python3，修了之后一切顺畅。

深夜给桌面上的文件收尾的时候，看了看今天的工作量：29 个文件在桌面和下载文件夹之间流转，20 条参考文献背后是 26 份原始 Tavily 搜索结果，论文从零到中期稿，全程 Cherry 一个人扛。
